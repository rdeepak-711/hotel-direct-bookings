2026-10-20 · DEC-7: "Book now" comes from the home page HTML, not from PageSpeed

Decided: bookNow and tapToCall are read from the hotel's home page HTML, which the gap check already downloads. PageSpeed is kept only for what it alone can see: the mobile speed score, HTTPS, and booking engines that load through JavaScript.

Considered: (a) keep the spec as written and read "Book now" from Lighthouse's link-text audit; (b) render every hotel page in a headless browser in production; (c) drop the "Book now" check.

Why: (a) cannot work. Lighthouse's link-text audit only lists links whose text is on a generic blocklist ("click here", "more"), so a "Book now" link never appears in it and every hotel would be told it has none. (b) adds a browser to a Vercel function: slow, heavy and costly for one field. (c) throws away one of the clearest signals of direct-booking readiness.

Cost: a "Book now" button that JavaScript draws after the page loads is not in the raw HTML, so it is missed and the hotel is wrongly told it has none. How often that happens is unknown until it is measured.
